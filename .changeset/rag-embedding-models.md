A collection can be embedded by any of several embedding models, each served by its own endpoint: `RAG_EMBED_MODELS` names more models besides `RAG_EMBED_URL`'s (named by `RAG_EMBED_NAME`), each with its URL, the prompt its questions get (`query_prompt`, a prompt from the model's own configuration, such as Qwen3-Embedding's `query`; `RAG_EMBED_QUERY_PROMPT` for the default) and its Workers AI counterpart and batch. `create_collection` takes `embedding_model`, and a collection keeps the model it was built with, found again by the model and revision it recorded. `search` over collections built with different models embeds the question once per model and fuses each model's nearest chunks as a list of its own; `index_path` reports the model by name. Each collection now has an HNSW index of its own, partial on its name, so collections from different models never share a graph: a new collection gets it at once, `create_collection` with an existing collection's name builds it concurrently and drops the index all collections shared once none needs it, and `health` lists the collections still without one. `health` lists every embedding model, the default first.
