A client held to a ceiling (`MCP_CLIENT_MAX_ACCESS`) may now fetch from `GET /files/outbox/<path>` the files its own calls handed back, and nothing else. Before, it was refused every file, so a client allowed only `read` tools could call a tool that saves an e-mail attachment, an invoice archive or a downloaded document and links it, and then could not fetch the very file its call produced. A file counts as its own when the call's code saved it through the kit's outbox writer (`saveToOutbox`, `noteHandedBack`) and the call succeeded; a link a result merely carries does not count, so a tool that echoes a link it was given opens nothing. Every other request from such a client is still the same 403: any upload, another client's file, a guessed path, a path out of the outbox, and its own path once another file or a link is there. The server keeps these records in memory, at most 10,000 per client, for as long as `MCP_HTTP_FILES_MAX_AGE_MIN` keeps the files, or 24 hours when it is unset, and forgets them on a restart: a fetch after one is refused, and calling the tool again brings the file. The 403's words now say so. A client with no ceiling is served exactly as before, and there is no new setting.
