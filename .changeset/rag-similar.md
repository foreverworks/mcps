`similar` finds the documents in a collection that say most nearly the same thing as one of its documents: duplicates and near-duplicates to merge, related documents, or a document's closest neighbours before you write a new one. Give it the document's source as `list_sources` and `search` show it, and it returns the closest `limit` (10) documents, best first. Each has a `score`, the mean of `forward` and `backward` (how much of the named document is found in it, and how much of it in the named document): 1 for identical text, the same whichever of the two you start from, and in principle below 0 for opposite ones, which the default `min_score` of 0 leaves out. Each also has its `chunks` and the closest pair of passages by chunk id and location, which `expand` reads. `candidates` (10) sets how many nearest chunks each chunk of the named document contributes when the candidate documents are found. A document of more than 64 chunks, the named one or a result, is compared by 64 spread evenly through it, and the reply says which (`sampled`, on the reply and on each result). It compares the vectors already stored, in one query through the collection's own vector index, so no embedding model is called, and a call that runs past 15 seconds is cancelled with an error that suggests a smaller `candidates`. It is a `read` tool: it changes nothing.
